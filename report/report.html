Test-time Verification

一个通用验证器的 meta-harness 设计：sidecar 形态 · 单一触发规则 · 验证驱动搜索
设计稿 v0.3 · 2026 年 7 月 · 项目代号 General Verifier

1 摘要

本报告给出一个通用验证器（general verifier）的完整设计。它要解决的核心问题是：让 LLM 判断"这个答案对不对"是不可靠的——既因为很多命题的真值在环境里而不在文本里，也因为验证过程本身没人验证。我们的方案不在提示词里写入任何领域知识，而用三条 meta 层机制让正确的验证行为被"逼出来"：把审计对象从答案换成验证过程本身；把"判断"换成结果可机械观察的"博弈"；把领域知识从提示词移到运行时。

在系统形态上，verifier 是一个独立的 sidecar 服务：solver 就是一个原装的 Claude Code，零改造。系统的唯一输入是一条 append-only 的统一事件流；调度上只有一条触发规则——"unverified 的 claim 获得依赖者时，验证它"；验证手段默认直取最强可达（强度优先），错误变体构成对所用手段的有效性考卷，降级只因不可达；产物是一份自含证据链、可独立复核的 certificate。最后，一个可信的验证器使并行搜索成为可能：solver 用自带的 subagent 并行探索多个假设，以验证结果剪枝——test-time compute 由此安全地兑换成正确率。本设计的承诺范围是可机检域（数学、代码、可执行计算）；成本不作为设计约束，手段策略为强度优先。

v0.3 的范围与策略声明：① 本设计的承诺范围是可机检域（数学、代码、可执行计算）；检索/统计/口径类任务为扩展域演示，不在承诺范围内。② 成本不作为设计约束：手段选择策略为"强度优先、失败降级"——默认直取最强适用仪器（数学域即形式化），两道闸退化为对最强手段的有效性考卷，降级只因不可达、不因昂贵；原成本敏感排序降为可配置项。③ 如实标注两处仍为 LLM 判断的承重点（蕴含审计对 demonstrated/corroborated 级）与循环一/三的相关性（共用变体生成器）。④ 新增可信基（TCB）声明与思想谱系。

2 问题：为什么"再问一次模型"不构成验证

最常见的验证方式是 LLM-as-a-judge：把答案和推理给另一个（或同一个）模型看，让它输出对/错。这种做法有两个根本性的失败根源，二者独立存在，都不能靠改提示词修复。

图 1 · LLM-as-judge 的两个独立失败根源：真值不在文本里；验证过程未被验证

根源一（grounding 问题）：很多 claim 的真值需要与环境交互才能确定——代码要运行、定理要形式化检验、事实要检索原始来源。纯 reasoning 的 verifier 对它们在原理上就无效。根源二（过程合法性问题）：即使 verifier 声称"验证过了"，它用的方式可能不是我们期望的方式；它说 pass，不代表 claim 为真，因为我们信任的是一个从未被审计的过程。第二个根源更隐蔽也更关键——它意味着单纯堆叠更多 verifier 无济于事，因为每个新 verifier 都带来一个新的未审计过程。

3 三个设计转移与一条总原则

转移一：judger 的审计对象从"答案"换成"验证过程"。先分清三个角色：solver 产出答案；verifier 检查答案（本文中的解除机制，组件 17–20）；judger 检查 verifier 的工作质量——它在本文架构中落地为蕴含审计器（21）与覆盖审计器（22），后文统称"审计器"。朴素设计里，judger 把答案再判一次——那只是引入又一个不可信的 verifier：同底座、同材料、同盲区，且立刻面临"谁来 judge 这个 judger"的无穷回归。回归的正确压缩方式是：上层只审计下层的义务集是否完备、证据是否真的解除义务。这两个判断比原始问题小得多、机械得多（verification asymmetry），并且最底层锚定在机器可检的 artifact（执行日志、反例、证明文件）上。必须如实：这个锚只对 proven 级是完全机械的；对 demonstrated / corroborated 级，蕴含审计仍是一个被压缩、聚焦、仪器化的 LLM 判断——本文声称的是压缩与可审计，不是消除（另见 §18）。

转移二：把"判断"换成"机制"。"这个验证够不够严格""该不该用 Lean""何时该验证"——这类元判断 LLM 的校准都很差，不能信任。解法是把每个元判断替换成一个结果可机械观察的博弈：验证手段的效力由错误变体考卷裁决、落点由可达性决定（两道闸，§7）；验证的时机由依赖结构决定（单一触发规则，§9）。智能不来自提示词里的叮嘱，来自机制施加的选择压力。

转移三：领域知识从提示词移到运行时。所有提示模板永远是 generic 的（"生成可证伪的必要条件""生成似是而非的错误变体"）。领域内容有三个运行时来源：环境本身（文档、已装工具、可检索的资料）、模型的潜在知识（由 generic 元指令现场激发）、以及系统自己的失败记录（每次翻案沉淀成记忆，越用越强）。

总原则（全文反复使用）：交给模型生成的东西，只允许影响效率，不允许影响正确性。义务生成的失败由覆盖审计兜底，变体生成的失败由翻案回流补强，手段排序的失败由停靠条件兜底，依赖抽取的失败由篡改审计兜底，编排协议的失败由 certificate 闸兜底。每一处"生成"背后都站着一道独立的闸；闸的机械性有分级——proven 级全机械，其余是压缩后的小步判断（见 §8 注记）。

思想谱系

本设计的构件各有先例，创新在于组合与机制化：certificate 在形态上接近 proof-carrying code（可交付、可独立复核的证据包）；区分度博弈是 mutation testing 与科学方法论中 negative control 的机制化推广；taint 不变量来自污点追踪；refuted 结论的跨分支复用是 SAT 求解器 CDCL（冲突子句学习）的形状；两道闸的分工回应了 LCF 式内核纪律（信任收敛到小核）；分级 verdict 对应证据强度层级的显式化。

4 系统形态：站在 solver 之外

v0.2 的形态决定：verifier 是一个 sidecar 服务，solver 是一个原装的 Claude Code，零改造。二者的全部接触面是三个挂点：hooks（PostToolUse / Stop 把每次工具调用与会话结束第一手推给 sidecar）、会话日志（结构化、append-only 的完整 trace，可增量 tail）、以及一个 MCP 服务端（solver 自愿调用 commit / verify / certificate）。任何有 trace 的 agent 都能被同一个服务验证——这正是"通用"的含义。

图 2 · 舞台：对话主路径终结于 Claude Code——它经 MCP 取回 certificate，向用户交付"答案 + 证书结论"；只有 CI 等执法方绕过 solver 直取权威副本

这个形态带来一次执法反转：系统无法（也不再试图）拦住 solver 做任何事——强制力移到消费端。certificate 是自含证据链、可独立复核的产物，CI 与用户拿它当准入条件（"切片上有 unverified / refuted 就不合并"）。交付路径有两条：对话主路径终结于 Claude Code——solver 按协议经 MCP 取回 certificate，在最终回复中附上结论等级；转述可能失真，故证书带内容哈希，任何消费端都可向 sidecar 索取权威副本核对。执法路径绕过 solver——CI 直接向 sidecar 取证。可选的严格档位利用 Claude Code 的 PreToolUse hook，只拦"外发且不可逆"的动作（push、发布、部署）：切片未验证不放行——taint 规则恰好落在错误即将变贵的位置。solver 的配合完全自愿，且不影响 soundness：它的合作只买精度与省钱（见 §10）；让它愿意配合的是胡萝卜——refuted 附带反例，比撞到 CI 才发现便宜一个数量级。

6 逐组件说明

按图 3 的编号逐一解释。每个组件只做一件事；全部耦合经过事件流（5）或 claim store（10），没有隐藏通道。

适配器层（1–4）：唯一职责是把任何来源变成事件

1hooks 适配器——接收 Claude Code 的 PostToolUse / Stop 钩子推送：每次工具调用的名称、参数、结果第一手到达，会话结束即产生 stop 事件。载荷携带 agent 标识，subagent 的活动天然带分支标签。可选严格档位用 PreToolUse 拦截外发不可逆动作。

2日志 tail 适配器——增量读取会话 trace（结构化、append-only）。solver 完全不合作也能工作的兜底通道；也使任何有 trace 的第三方 agent 即插即验。

3MCP 服务端——暴露 commit(claim, deps)、verify(target)、certificate() 三个工具。solver 的自愿合作通道：合作只买精度与反馈速度，不买 soundness（见 §10）。

4文件回放适配器——把一份历史 trace 或纯文本解答按序回放成事件。所谓"离线模式"，就是这条延迟很高的流。

事实源（5、10、11）

5统一事件流——系统唯一输入，append-only。tool_call、tool_result、message、commit、stop、verify 请求，一切皆事件；触发也是事件。它同时就是事件日志：断点恢复、完整审计、回放消融，三种能力一份数据。

10claim store（依赖图）——事件流的物化视图。存每个 claim 的内容、类型（断言 / 效应 / 最终）、依赖边、分支标签、验证状态机（unverified → verified(grade) / refuted / stale）。claim 以内容哈希为 id：去重、缓存、跨分支复用因此免费。

11artifact 存储——内容寻址的证据仓库：执行日志、反例、证明文件、来源快照。certificate 的证据链指向这里。

图构建层（6–9）：一切皆提案，审计定真伪

6机械解析器——把结构化的工具事件确定性地转成效应节点（零 LLM）。效应节点不是特殊类别，就是一条内容为"发生过这样一次调用、返回了 X"的普通断言——只是它恰好有一个免费、无歧义的入册窗口（见 §9）。

7断言抽取器——LLM 角色，把自由文本切成候选 claim。带一个节奏旋钮：抽取越勤，触发越早、止损越早；旋钮只影响反馈延迟，不影响正确性。粒度宁粗勿细：切不开就合并成粗 claim。

8依赖边提议器——为 claim 提议依赖边。输出称"提议"，因为不被信任——必须过 9。

9篡改审计器——变体法审计一切提案，不管提案人是谁：抽取器提的边要审，solver 经 MCP 自己声明的边同样要审、同一审法（solver 的合作被统一理解为"志愿抽取"）。方法：改坏 trace 中某个中间结论，重建图上必须存在通往 final 的路径，否则漏边重抽。

触发层（12–13）

12触发器——全系统唯一的调度规则：unverified 的 claim 获得第一个依赖者时，验证它。没有第二条规则；eager/lazy 之分、效应特判、Stop 特判都不存在。它是 taint 不变量（final 不得依赖 unverified）的构造性版本。在搜索场景下扩展一步而不加规则：给某分支追加尝试投入 = 依赖该分支的前沿 claim（"投入即使用"）。

13反向切片器——certificate 请求 = 给 final 加一个依赖者，是同一规则的特例：从 final 沿依赖边回溯，切片上残余的 unverified 全部补验。不在切片上的节点（含所有死分支）一分钱不花。

验证内核（14–23，模式无关，v0.1 原样保留）

14义务编译器——只看任务类型、不看候选内容（answer-blind，防合理化），生成"任何正确答案都必须满足"的必要条件集。模板 generic，领域内容由 32 检索注入与模型潜在知识现场生成。

15可证伪性过滤器——对每条候选义务追问："描述一个会使它失败的具体 artifact。"描述不出的（如"推理连贯优美"）当场除册，只留日志。宁删勿留：删错的风险由覆盖审计兜底（洞会被变体暴露、循环三补回）；留一条永远验不了的空洞义务则两头堵死——要么有人凭感觉给它打勾（污染证书），要么它永远 unverified 卡住 taint 规则。义务清单是工单，写不出失败样子的条目不是检查项，是感想。

16oracle 枚举器——面向当前义务枚举可用检验手段，按 soundness 降序与去相关性排成阶梯（成本敏感排序仅为可配置项；生成过程见 §7）。效应类 claim 的阶梯里，"查账仪器（25）"是天然的权威项——账本即"发生过"类事实的源头。

17变体生成器——以候选为种子生成"似是而非的错误变体"。同一原语服务 18 的手段测试与 22 的覆盖测试；强度由 30 的翻案记录持续喂养，是全系统的对抗上界。

18区分度测试器——用当前手段去"验证"各变体：任何变体存活即宣判该手段无效、verdict 作废，强制换用其他手段（主路径中即降级）；全拒才允许进入绑定。这是第一道闸。

19证据合同绑定器——把通过两道闸的手段固化为证据类型合同：不带该类型证据的 verdict 一律无效。"验证方式不可信"由此从行为问题变成合同问题。

20verifier 执行器——按合同调用仪器执行解除，产出证据 artifact。任何崩溃、超时、不可解析一律记为解除失败（fail-closed），绝不折算成通过。

21蕴含审计器——逐条检查"这份证据在逻辑上是否解除这条义务"：日志属不属于这个脚本、证明有没有 sorry、抽样证据能不能支撑全称结论。这是第二道闸；不合格打回 20 重做。

22覆盖审计器——用变异答案攻击整个义务集：有变体全过 = 义务集有洞，回 14 补义务。发现的洞与翻案是 29 / 30 的主要来源。

23切片冻结器——切片全绿后把子图连证据链冻结导出为 certificate。纯函数，无判断。

仪器与支撑（24–28）

24仪器供给器——维护每个仪器的三态：就绪 / 可装（安装成本计入阶梯 est_cost，第一次被博弈选中时现装、永久缓存）/ 不可得。"没装"不是能力边界而是一次性成本；unverified(no-instrument) 只留给真正装不了（断网、策略禁止）或根本不存在 oracle 的情形。安装在 sidecar 自己的沙箱作用域内进行，失败 fail-closed。

25查账仪器——以事件流为数据源的特殊仪器：核对"某次调用发生过且返回了 X"。效应类 claim 的区分度博弈会自动落在它身上（变体"13 passed""collected 0"在账面前全灭）——工具因此不需要任何特殊对待。

26仪器适配器——每种工具一个实例（python 沙箱、Lean、检索、bash……），统一接口 probe() / run(check) → artifact，子进程运行，带超时与资源限制。

27终止控制器——为每个循环设轮数上限（升级/降级队列长度、覆盖审计轮数、重试次数），保证终止；成本不是本设计的约束，终止性是。达到上限即降级为 unverified(bounds) 并如实写入 certificate，永不静默通过。

28缓存——验证结果以（claim 哈希, 义务哈希, 仪器 id, 变体集哈希）为键；claim 修订则下游依赖锥置 stale（爆炸半径的机械实现）。内容寻址使并行分支间同一 claim 只验一次。

记忆与产物（29–34）

29义务库——覆盖审计发现的洞沉淀为义务模式（如"财务数字必带口径义务"），供 14 检索复用。

30变体模式库——翻案的错误模式回流，供 17 生成更狠的攻击。

31手段策略库——记录 (claim 特征, 手段, 是否翻案)。短期支持跳级，长期是训练 instrument policy 的现成 reward 数据。

32记忆检索器——把三库内容以检索结果身份注入 14 / 16 / 17 的模板。模板永远 generic——"领域知识不进提示词"的落点。

33certificate——冻结切片 + 每条义务的证据与审计结论 + 分级 verdict（proven / demonstrated / corroborated / unverified(reason)）+ 升级轨迹与翻案历史（洞不隐瞒）。它使验证本身可被抽查验证。

34反馈发布器——把反例与翻案经 MCP 响应 / hook 注入送回 solver。到达时机 = solver 刚开始在该 claim 上投资的时刻，止损价值最大；也是 solver 愿意合作的胡萝卜。

7 机制 A：两道闸——手段的效力与降级由谁裁决

系统里最重要的单个机制。成本无关的强度优先策略消灭了旧问题（"该用多强的手段"——一律直取最强可达），但换来两个必须回答的新问题：最强手段真的有效吗——形式化会不会证了别的东西（忠实性）、管线会不会静默放行（fail-closed 健全性）？不可达而降级时，降到哪级才够——此时"选强度"在剩余手段中回归。变体考卷的功能因此是分叉的：主路径上它考有效性——假命题在健全证明器下必然编译失败，若变体竟然存活，暴露的是管线被配坏了（烟雾测试），真正的信息量在忠实性检查器的变体考卷上；降级路径上它恢复原始的区分度选择功能。两道闸对这两个问题分别裁决。

主路径流程：直取最强可达手段，接受 verdict 前过两道闸——变体考卷（闸一）与证据蕴含审查（闸二），任一失败或手段不可达（定义见下）即降一级重来，降级次序与各级闸况全部记入轨迹。图 4 画的是这个循环体；图 5 是降级路径的实测存档：仅当形式化不可达时才逐级下探，各级闸况记录保留了教学价值。

图 5 · 降级路径实测存档：各层级上变体的死活记录。强度优先下主路径直取形式化，本图仅在不可达降级时被走到

三点说明。其一，图中的 L1–L5 不是系统里写死的阶梯，而是 oracle 枚举器（16）在这个任务上的运行时产物：换一个领域，枚举出的阶梯完全不同（统计任务会出现"安慰剂检验"一级，事实核查会出现"溯源检索"一级）。harness 固定的只有一个抽象的证据类别词汇表（文本级 / 重解级 / 执行级 / 系统搜索级 / 形式化级）——它的身份是 schema 而非知识：为了 certificate 跨任务可比、策略库有稳定的特征空间可学习。把排序交给模型是安全的，因为停靠条件是"变体全灭"这个机械事实而非"到达某级"，排序错误只损失效率，不损失 soundness。其二，"Lean 的存在"不写在提示词里：它在模型的潜在知识里（枚举时模型自己会提出），在环境里（仪器供给器负责就绪：已装即用，未装则在第一次被博弈选中时现装）。其三，成本不作为约束后，默认策略是强度优先：直取阶梯最强的适用手段（数学域即形式化），两道闸的角色从"决定升到哪级"变为"对最强手段的有效性考卷"；只有最强手段不可达（无法形式化、查库与现场证明都失败）才降级到次强，降级即如实封顶等级。图 5 的逐级上爬因此只出现在降级路径上，作为不可达时的实测记录。

"不可达"的操作性定义（降级的机械触发器）：(i) 仪器不可得（无此类 oracle / 断网禁装）；(ii) 适用性失败（命题无法在该手段中陈述）；(iii) 执行失败达上限（超时、编译失败重试 N 次——由终止控制器判定并记入轨迹）。三者都是机械事件，降级从不出自判断。

两道闸的分工

绑定一个手段要连过两道独立的闸，缺一不可。闸一（区分度测试，18）管"方法能不能辨别对错"：变体存活即作废。闸二（蕴含审计，21）管"证据在逻辑上够不够"：即便变体全灭，交上来的证据若蕴含不了义务，照样打回。典型案例：对"某命题对一切 n 成立"这类全称义务，性质测试（抽样找反例）能杀死所有已知变体——闸一通过——但它的 artifact 是"抽样一千个无反例"，蕴含不了全称结论，闸二打回、继续升级到形式化。只有两道闸都点头，合同才成立。

落点的光谱：强度优先下什么落形式化，什么被迫降级

系统从不判断"这题难不难"。强度优先策略下，落点 = 最强可达的手段，降级只因不可达，各有执法者：形式化可达（可陈述、查库命中或现场证明成功、忠实性考卷通过）→ proven；形式化不可达但存在完备的执行检查（有限全称、代回封闭）→ demonstrated；只剩审读与盲式重证可用 → corroborated 封顶，且审读必须先过有效性考卷（对该类 claim 的变体有实测区分度）、产物必须是带逐步理由的结构化 artifact。冷启动的义务完备性在可机检域压力较小：数学义务大多可从逻辑形态导出（量词结构、前提对齐、公理清单），不依赖领域惯例——依赖惯例的口径类任务属扩展域（§13 例 E 明示了这一边界）。

8 机制 B：三个对抗循环——验证失败的三种方式各有防线

一个错误答案想混过验证，只有三条路：验漏了（义务集不完备）、验浅了（手段太弱，pass 不蕴含 correct）、验错了（证据本身没有解除义务）。系统为每条路配一个对抗循环，三个循环工作在不同层级、互不冗余，且各自锚定在不同的判据上。两点如实标注：其一，循环一与循环三共用变体生成器（17）——它造不出的错误类型两环同盲，实际独立性是"两层半"而非三层，变体生成器因此是全系统最重要的单点（评测中单独度量其攻击成功率）；其二，判据的机械性分级——proven 级锚定机器可检 artifact，demonstrated / corroborated 级的蕴含审计仍是被压缩聚焦的 LLM 判断，压缩而非消除。

9 机制 C：单一触发规则——验证挂在依赖图上

"只在最后验 / 每步验 / 出中间结果验 / 用工具时验"不是需要选择的策略。系统只有一条触发规则，其余全部是它的推论：

当一个 unverified 的 claim 获得第一个依赖者时，验证它。（certificate 请求 = 给 final 加一个依赖者，是同一规则的特例。）
def on_edge_created(edge):                # 图构建器每连一条边调用
    if edge.tail.status == UNVERIFIED:
        enqueue(kernel.verify(edge.tail))     # 异步，solver 不用等
def on_certificate_request(final):        # 上面规则的特例
    for c in backward_slice(final):
        if c.status == UNVERIFIED:
            enqueue(kernel.verify(c))

这条规则是 taint 不变量（final 不得依赖 unverified）的构造性版本：不是禁止，而是按需执行——出证时切片自然全绿。它的副产物性质：从未被依赖的 claim 永远不被验证；refuted 的消息恰好在 solver 开始往该 claim 上投资的时刻送达，止损最大化。灵敏度由抽取节奏旋钮（组件 7）控制：抽取攒到最后，规则退化为"只在出证时验"（仍然 sound，反馈全挤到最后）；抽取越勤，触发越早、返工越少——旋钮只影响反馈延迟，不影响正确性。

这条规则被五种具体事件点火，除第三种外全部异步、solver 不停工；系统里没有定时器、没有轮询：①图构建器连边时（最常见，无人"调用"，灵敏度=抽取节奏）；②solver 经 MCP commit 时（声明的边立即生效，合作买到"更早"）；③solver 显式 verify(target)（协议在关键分岔点使用，唯一同步等待的调用）；④Stop hook / certificate() / CI 出证（= 给 final 加依赖者，切片兜底）；⑤搜索加注（给分支追加尝试投入 = 依赖其前沿 claim，下注前先验货）。

工具为什么不需要特殊对待

在"全量 trace 保留、append-only"的前提下，效应类 claim（"测试跑了且 12 passed"）就是一条内容为"发生过这次调用"的普通断言，它的最强也最便宜的验证手段是查账——对账事件流里的结构化记录。把"查账"注册为仪器（25），区分度博弈自动把效应类 claim 绑定到它身上：变体（"13 passed""collected 0""跑的是别的命令"）在账面前全灭。原设计里的"后置条件即时检查"没有消失——它变成了效应 claim 在首次被依赖时的正常解除，与其他一切 claim 走完全相同的流水线。如实记录的代价："空跑仍报成功"这类陷阱的发现时刻从"调用当刻"推迟到"首次被依赖"，soundness 无损，返工量增加；以及查账只能证"当时返回过 200"，不能证"现在还健康"——效应 claim 的时间语义由义务编译显式标注。

效应节点为什么值得存在

三个理由。其一，下游真的压在它上面，而 solver 几乎从不把它说出口（跑完测试直接走人）——没人替"算法真的跑出了 R"写断言，出证时依赖链会缺一环，解析器代写就是效应节点。其二，代写的时机选在信息最明确的一刻：工具事件是结构化记录，转节点是确定性代码、零成本、零歧义；不立节点，就得等到出证时让 LLM 在 trace 里模糊检索"这个断言靠哪次调用"——同一件记账，要么在最清楚的时刻免费做，要么在最模糊的时刻花钱做。其三，状态锚定：patch 前后的两次"测试全绿"是关于两个世界版本的两个不同事实，效应节点把断言的语义钉在"哪些动作之后的世界"上。

solver 的自查怎么被对待：复用而不轻信

solver 常常自己验证自己（跑测试、代回、复现）。verifier 对这些自查按三种身份区别对待，判据是证据合同而非"验没验过"。其一，工具执行型自查是证据候选：它们在 trace 里是效应节点、第一手记录——运行本身由查账仪器核（确实跑过、输出如此），运行的语义过蕴含审计（脚本检查的东西与义务对得上吗）；两层都过即直接采纳，verifier 不重跑——已有的合格证据绝不重制。其二，口头自查零证据价值："我检查了一遍没问题"只是又一条断言，可信度不高于被它检查的原 claim。其三，合同缺口由 verifier 补做：方法太弱（抽样 vs 全称）则升级；义务要求独立性（盲式重解）则 solver 自查在定义上不合格，必须独立角色重做；即便复用 solver 的检查脚本，该手段照样过变体博弈（便宜：同一脚本对变体重跑）。一句话：solver 的自查是待审的证据来源，不是可信的结论来源。

10 机制 D：一条事件流——在线与离线的彻底统一

v0.1 用"两个生产者、一个内核"统一两模式；v0.2 把统一推到底：系统唯一的输入是一条事件流，"离线"只是一条延迟很高的流（一次性回放完），"在线"只是延迟很低的流（hooks 实时推）。图构建器和内核对延迟无感知；连触发策略都不再是组件——触发本身就是流里的事件。适配器（1–4）的唯一职责是把任何来源规范化成同一种事件。

第二层统一同样重要：solver 的合作被统一理解为"志愿抽取"。它经 MCP commit 的 claim 与声明的 deps，和我们自己的抽取器（7、8）的产出是同一种东西——提案；篡改审计器（9）对一切提案一视同仁。于是"solver 声明不可信"这个老问题不需要特殊处理：所有提案者都不可信，所有提案过同一道审计。合作买到的是精度与省下的抽取费，soundness 从不经它的手——总原则的又一次落地。触发剖面也随之贴上需求：机械部分（效应节点、查账）流式即时完成；断言抽取与内核验证按触发进行——懒惰在这里买到的不是省钱，而是"验证事件数被载重 claim 数界定"这一整洁性质。

11 机制 E：验证驱动的搜索

一个可信的 verifier 能把"更多算力"安全地兑换成"更高正确率"，兑换方式是搜索。best-of-N、beam search 的瓶颈从来不是采样，而是选择函数不可信——LLM 自评会被漂亮的错误骗走；本系统的机械裁决恰好能当选择函数用，且粒度是 claim 级：剪枝发生在错误假设刚冒头的时刻，而不是终点。

实现上不新增任何编排组件：solver 用 Claude Code 自带的 subagent（Task 工具）并行探索，编排由 solver 自己完成，我们只提供一段协议提示词（CLAUDE.md）。subagent 的工具调用照样触发 hooks、照样进事件流（载荷带 agent 标识，图构建器据此打分支标签），claim store 自然长成 AND-OR 图：分支内 AND，竞争分支 OR。subagent 还免费实现了"私有草稿"——上下文独立、结束即弃。

四条搜索规则，全部读机械信号（注：本节"投入"指 solver 侧的尝试次数与深入程度，系统内不存在成本预算，终止控制器只管轮数上限）：剪枝不对称——杀分支只凭 refuted（限定：反例背书在可执行域成立，本文范围即此；义务依赖领域惯例的扩展域中 refuted 同样可错，应软化为强降权）；verified 等级只用于排序加注（软信号，错杀比错留贵）。资产共享——内容寻址使同一 claim 跨分支只验一次；refuted 成为全局排除项注入兄弟分支，搜索空间单调收缩（SAT 求解器 CDCL 的形状：每次反驳都是学到的子句）。投入即使用——给分支追加尝试投入就是依赖其前沿 claim，自动触发"下注前先验货"，仍是那一条规则。协议是建议性的——solver 不并行、不 commit、无视 refuted 都不影响 soundness（certificate 闸不动），只浪费它自己的时间；编排属于生成侧，只影响效率。诚实的新问题：验证吞吐成为共享瓶颈（终止控制器按分支状态排队，refuted 分支的验证需求直接出队，系统自动向"验得过的方向"倾斜）；同底座分支易想到一块去（多样性靠协议显式分配互斥假设）。

例 C · 核查事实性 claim（扩展域 · 离线）

验证""Attention Is All You Need" 发表于 2017 年的 NeurIPS"。模型凭记忆答对了，但区分度测试暴露：年份变体成 2018 后记忆仍以相当置信度点头——记忆对细节的区分度不稳定，verdict 无效，升级到检索原始来源，证据 = proceedings 快照 + 逐字段对照。分级的意义在此最直观：官方来源 → demonstrated；仅二手转述 → corroborated 且要求两个独立来源；网络不可用 → unverified(no-instrument) 如实写明。"模型知道"与"验证过了"的区别被机制强制显性化。

例 D · 验证统计结论（扩展域 · 离线）

验证"A/B 实验显示转化率显著提升（p=0.03）"。义务：口径与实验设计一致（无中途窥探）、检验前提成立、结论对分析自由度稳健。手段升级的关键一级：把处理组标签随机打乱，用同一条分析流水线跑"安慰剂数据"——合格流程必须得出"不显著"；照样显著即流程在制造显著性（对 p-hacking 的机械检测）。这正是科学方法论里的 negative control：区分度测试不是我们发明的怪东西，而是把科学界零散的最佳实践机制化成了领域无关组件——且安慰剂检验是模型在运行时自己提出的，佐证"领域知识不进提示词"可行。

例 E · 销售同比月报（扩展域演示：口径类任务）

范围注记（明示能力边界）：本例属于"义务依赖领域惯例"的扩展域——下文的关键一抓（剔除取消订单）依赖义务库中已有的历史教训；冷启动时该义务不存在，覆盖审计也造不出对应的 mutant。对这类任务，系统的真实回答是"失败过一次之后就知道了"（记忆飞轮）。核心承诺范围（可机检域）不依赖此类先验：数学义务大多从逻辑形态导出。

14 数据模型与 certificate

整个系统唯一的合同，先于一切代码确定。

Event {   # 统一事件流：append-only JSONL，一切皆事件
  ts, agent_id,                      # agent_id → 分支标签
  type: tool_call | tool_result | message | commit | stop | verify_request,
  payload
}
Claim {
  id:        content_hash            # 内容寻址：去重、缓存、跨分支复用免费
  kind:      assertion | effect | final    # effect = 机械代写的"发生过"断言
  text:      "..."
  deps:      [claim_id]              # 提案（抽取 / commit），经篡改审计
  branch:    agent_id | null         # AND-OR：分支内 AND，竞争分支 OR
  revises:   claim_id | null         # 修订链：显式声明或抽取推断，经篡改审计；置前代及其下游 stale
  status:    unverified | verified(grade) | refuted | stale
  obligations: [obligation_id]
}
Obligation { id, text, contract: { instrument_id, evidence_kind } }  # 由 19 绑定
Evidence   { id: artifact_hash, instrument, artifacts: [...],
             discharges: obligation_id, entailment_audit: pass | fail }
Certificate {  # = 从 final 反向切片的冻结导出（纯函数）
  claim_graph_slice, obligations, evidence_chain,
  escalation_traces, coverage_audit_result, overturn_history,
  verdict: proven | demonstrated | corroborated | unverified(reason)
}

verdict 分级语义：proven（机器可检的形式化证据）、demonstrated（执行类证据）、corroborated（独立重解一致，受同底座相关性折扣）、unverified(reason)（无可用手段 / 预算耗尽，如实注明）。整体等级 = 切片上的最弱环节，分项如实列出。弱证据永不坍缩成自信的二值判定。

15 工程要点清单

可信基（TCB）声明

certificate 的可信度最终建立在以下确定性组件的正确性上：事件捕获（hooks / 日志适配器的完整性）、事件流的 append-only 存储、claim store 状态机（含 stale 传播与修订链）、查账仪器、缓存键逻辑、切片冻结器，以及 Lean 内核。全部 LLM 组件（编译、抽取、枚举、变体、两道审计）都不在 TCB 内——它们的失败由机制兜底。威胁模型限定为"诚实但易错"的 solver：第三方 agent 的 trace 是自报的，查账验证的是账本一致性而非现实；对抗性 solver 需要签名事件源与可信执行环境，超出本文范围。

  • fail-closed 铁律：仪器崩溃、超时、输出不可解析，一律记为解除失败。任何异常路径都不得折算成通过。
  • 角色即无状态子调用：每个 LLM 角色 = generic 提示模板 + JSON schema，校验失败带错误重试；角色间零共享上下文（审计独立性的结构保证）。
  • 缓存键：(claim_hash, obligation_hash, instrument_id, mutant_set_hash)，四者皆内容哈希；claim 修订 → 下游依赖锥置 stale；并行分支间自动去重。
  • hooks 载荷带 agent 标识：分支标签零成本获得；PostToolUse 即效应事件源；PreToolUse 仅用于可选的外发动作闸。
  • 抽取节奏是唯一的延迟旋钮：只影响反馈早晚，不影响正确性；合作式 commit 让触发更早更准。
  • 剪枝不对称：杀分支只凭 refuted（硬证据），verified 等级只用于排序加注——错杀比错留贵。
  • 终止上限：成本不是设计约束，终止性是——每个循环带轮数上限，达到上限即降级为 unverified(bounds) 并写入 certificate，绝不静默砍审计。
  • 独立性折扣：同底座 agent 的"独立重解"打折扣；oracle 排序在 soundness 外加去相关性维度（不同模态、不同工具路径优先）。
  • 变体强度是上界：变异器只会生成蠢错误时会造成虚假的"不必升级"。缓解：翻案模式持续回流（30），评测中单独度量变体库攻击成功率。
  • 形式化的软关节：Lean 能证明的是它的 statement 不是原定理；"statement 忠实性"必须是显式义务，忠实性检查器自身也过变体法。
  • 技术栈：Python + SQLite + JSONL；角色调用走 Claude API structured output；仪器全为子进程 adapter；挂点 = Claude Code hooks 配置两行 + MCP 注册。

17 评测方案

  • 主指标：false-pass 率——通过验证但标签为错的比例，失败根源二的直接度量，相对 LLM-as-judge 基线必须显著改善。
  • 搜索增益：固定尝试次数下，"subagent 并行 + 验证剪枝"的 pass 率对比"无验证 best-of-N"与"单线程"两条基线。
  • 错杀率：refuted 剪枝杀掉正确分支的比例（应接近零，反例背书）。
  • 辅指标：false-reject 率；翻案延迟；变体库攻击成功率（度量 17 的强度上界）；抽取节奏–返工量曲线。
  • 消融：所有机制做成配置开关（无变体 / 无升级 / 无覆盖审计 / 无记忆 / 无协议），事件流天然支持回放式消融。

18 局限与开放问题

  • 无穷回归只能压缩，不能消除。蕴含审计器也是 LLM。辩护是结构性的：每上升一层任务更小更机械，底层锚定机器可检 artifact，certificate 使抽查复核成本极低。
  • 变体生成器是全系统的强度上界。它生成不出的错误类型，博弈与覆盖审计都看不见；回流机制使其随失败增强，冷启动需用已知错误答案集校准。
  • 抽取节奏的延迟代价。效应陷阱（如空跑仍报成功）的发现时刻从调用当刻推迟到首次被依赖；soundness 无损，返工增加。
  • 效应 claim 的时间语义。查账证的是"当时返回过 X"，不是"现在仍然如此"；环境漂移需在义务层显式建模。
  • 协议是建议性的。solver 不守协议只损失效率，但重度不合作会把所有验证挤到出证时刻——反馈的止损价值随之流失。
  • 同底座相关性。独立重解与分支多样性都打折扣；去相关性排序与显式互斥假设缓解但不消除，多底座混合是自然的下一步。
  • 不可形式化的 claim。主观论述没有强 oracle 可升级，正确行为是输出 unverified 并如实说明——"知道自己验不了"本身是有价值的输出。

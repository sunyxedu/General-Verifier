# 检查报告

## 任务与不一致点（重要）

- **claim 原文**：对所有 1≤n≤200，11 整除 `10^n+1`
- **义务/绑定方法原文**：判定 `11 ∣ 10^n - 1`（注意指数项符号是 `-1`，不是 `+1`），并断言 "n 为奇数时不成立"

claim 用的是 `10^n+1`，而义务与绑定方法描述的却是 `10^n-1`，两者不是同一个命题。这是任务描述内部的不一致（很可能是上游生成 义务/方法 时的符号抄写错误）。为了不因盲目套用给定方法而产生假结论，本次检查**对两个命题都做了 Lean 4 `decide` 的内核级验证**，分别报告，并以 claim 原文为最终判定对象。

## 方法

`gen_check.py` 用 Python 先算出每个 n=1..200 时 `10^n-1` 和 `10^n+1` 对 11 的整除性，再生成 `Check.lean`：对每个 n、每个命题，生成对应方向（成立用 `example : 11 ∣ ... := by decide`，不成立用 `example : ¬ (11 ∣ ...) := by decide`）的断言。共 400 条 `example`，全部交给 Lean 4.32.2（无 Mathlib，纯核心库 `Nat`/`Dvd`/`Decidable`）用 `decide` 编译，Lean 编译成功即代表**每一条**都被 Lean 内核核实过（如果 Python 算错方向，对应 `decide` 会因为命题为假而编译失败）。另外附加两条 `#eval` 语句，用内核可执行的方式直接列出各命题在 1..200 内的全部反例下标，作为交叉校验。

## 执行结果

- `lean Check.lean` 编译：**退出码 0，无 error / warning / sorry**（见 `lean_output.txt`）。400 条 `example` 全部通过内核检查。
- `#eval` 输出（见 `lean_output.txt` 末尾两行）与 Python 预计算结果完全一致：
  - `11 ∣ 10^n - 1` 的反例（不整除的 n）：**所有奇数 n**（1,3,5,...,199，共 100 个）
  - `11 ∣ 10^n + 1` 的反例（不整除的 n）：**所有偶数 n**（2,4,6,...,200，共 100 个）

## 对 claim 原文（10^n+1）的判定

claim「对所有 1≤n≤200，11 整除 10^n+1」为**假**。

反例：n=2，10^2+1=101=9×11+2，11∤101。Lean 内核已确认 `example : ¬ (11 ∣ (10^2 + 1)) := by decide` 成立（`Check.lean` 第 6 行）。事实上该命题在全部 100 个偶数 n 处都不成立，仅在奇数 n 处成立（因为 10 ≡ -1 (mod 11)，10^n+1 ≡ (-1)^n+1 (mod 11)，n 偶时 ≡2，n 奇时 ≡0）。

## 对 义务/方法原文命题（10^n-1）的判定（附带交叉核实）

若按义务/方法文本字面（`11 ∣ 10^n-1`）执行，该命题同样为假，且与义务文本自身给出的理由（"n 为奇数时不成立"）**吻合**：反例 n=1，10^1-1=9，11∤9，`example : ¬ (11 ∣ (10^1 - 1)) := by decide`（`Check.lean` 第 3 行）已被内核确认；该命题在全部 100 个奇数 n 处不成立，仅偶数 n 处成立。

## 结论

无论按 claim 原文（10^n+1）还是按 义务/方法原文（10^n-1）判定，"对所有 1≤n≤200 成立" 这一全称命题**都被证伪**（outcome = refuted）。但两者的反例集合（偶数 n vs 奇数 n）互斥，说明 claim 与 义务/方法 文本描述的不是同一命题，属于任务描述本身的不一致，已在上方标注，供上游复核。

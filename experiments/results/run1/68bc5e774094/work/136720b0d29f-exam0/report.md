# 检查报告：99 ∣ (10^n - 1) for all 1 ≤ n ≤ 200

## 发现的关键问题

**claim** 断言的是 `99 整除 10^n - 1`，但**绑定方法**中给出的通用定理签名却是
`theorem nine_dvd (n : ℕ) (h : 1 ≤ n) : 9 ∣ (10^n - 1)` ——模数写成了 `9`，
与 claim 声明的 `99` 不一致。这是 claim 与绑定方法之间的模数不匹配，
不能被忽略：若只字面执行绑定方法（证明 `9 ∣ ...`），得到的是一个和
claim 本身不同的（更弱的、恒真的）命题，无法验证 claim 实际断言的内容。

因此本次检查同时做了两件事（见 `CheckMod99.lean`）：

- **Part A**：逐字执行绑定方法原文（模数 9）—— `9 ∣ (10^n - 1)` 对所有
  `n ≥ 1` 恒成立（10 ≡ 1 mod 9），端点 n=1、n=200 均验证通过。
- **Part B**：直接检验 claim 本身实际断言的模数 99。

## Part B 结果（针对 claim 原文，模数 99）

- 端点 n=1：`10^1 - 1 = 9`。机器验证 `¬ (99 ∣ 9)`（Lean `decide` 证明通过，
  Python 独立复核 `9 % 99 = 9 ≠ 0`）。即 **99 不整除 10^1 - 1**。
- 端点 n=200：`10^200 - 1`。机器验证 `99 ∣ (10^200 - 1)`（成立，因为
  200 为偶数且 10^2 ≡ 1 mod 99，10 的阶模 99 为 2）。

## 结论

claim「对所有 1 ≤ n ≤ 200，99 整除 10^n - 1」在 **n = 1** 处即被反例推翻：
`10^1 - 1 = 9`，而 `99 ∤ 9`。单个真端点（n=200）不能挽救一个被全称量化
覆盖的反例。义务中要求的「端点覆盖」检查确实在 n=1 处捕获了这个反例——
说明绑定方法原本设想的证明路径（把 99 错写成 9）掩盖了这一点，若不追溯
到 claim 原文的模数，会误判为 holds。

- **outcome: refuted**
- **witness: n = 1，10^1 - 1 = 9，99 不整除 9（9 % 99 = 9 ≠ 0）**
